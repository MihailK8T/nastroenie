# Безопасность «Настроения»

## Что проверено сейчас

- В репозитории нет Supabase-ключей, `service_role` и других секретов.
- Клиентский JS не использует `innerHTML` и `eval`; пользовательские строки выводятся через `textContent`.
- Внешних скриптов и CDN нет — только локальные `assets/site.js` и `assets/site.css`.
- GitHub Pages отдаёт сайт по HTTPS.
- Консоль на главной и странице тарифов чистая.

## Текущее состояние (важно)

Сайт пока демонстрационный:

- аккаунты, тарифы и монеты хранятся в `localStorage`;
- пользователь может открыть devtools и поменять себе тариф или монеты;
- пароль хэшируется PBKDF2 в браузере, но это не заменяет серверную аутентификацию;
- Supabase не подключён: предоставленный ключ возвращает `401 UNAUTHORIZED_INVALID_API_KEY_TYPE`, поэтому RLS и таблицы не проверены.

Для продакшена нужен серверный слой: Supabase Auth + RLS + RPC для покупок. Клиент не должен иметь права напрямую менять `plan`, `plan_until` и `coins`.

## После подключения Supabase

Проверить анонимным (publishable) ключом:

1. `select * from profiles` — не должен отдавать чужие профили.
2. `update profiles set coins = 999999 where id = auth.uid()` — должен вернуть отказ.
3. `insert into coin_purchases ...` — должен вернуть отказ.
4. `select * from plans` — должен работать, но только чтение.
5. `rpc('purchase_plan', { p_code: 'creative' })` — только для авторизованного пользователя.
6. `rpc('buy_coins', { p_coins: 500 })` — только для авторизованного, с записью в историю.
7. Повторный вызов `purchase_plan` с тем же тарифом должен продлевать срок, а не сбрасывать его.

## Правила ключей

- В браузере допустим только `sb_publishable_...` (или legacy anon).
- `service_role` и secret-ключи — только на сервере/в SQL Editor, никогда в `docs/`.
- Если ключ засветился в переписке или публичном репозитории, его нужно отозвать и выпустить новый.

## Ограничения GitHub Pages

Pages не позволяет задавать произвольные HTTP-заголовки, поэтому CSP и HSTS настраиваются только на своём домене/прокси. Для демо это приемлемо; для продакшена лучше Cloudflare/Vercel/собственный сервер.
